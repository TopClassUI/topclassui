## The three kinds

Every component is one of three kinds. The kind is shown on the chip beside its name.

| Kind | Chip | What it means |
|---|---|---|
| S - server | server - 0 KB | Renders on the server. No hooks, no event handlers, no client JavaScript |
| C - client | client - n KB | Needs the browser: a popup, a drag, a keyboard listener |
| Sp - split | split - 0 KB server + n KB client | The markup renders on the server and one small part hydrates. Tag is a server component until you pass `onRemove` |

## What may cross the boundary

Only what React can serialise: strings, numbers, booleans, plain objects, arrays and children. A function never crosses, except a Server Action.

```tsx
// app/page.tsx - a Server Component
<Command

  getKey={(c) => c.id}
  getLabel={(c) => c.label}
  onSelect={run}
/>
// getKey, getLabel and onSelect are functions:

```

## Why index.tsx has no hooks

Markup lives in `index.tsx`, behaviour in `hook.ts`. `index.tsx` never contains `'use client'` and never imports `hook.ts`. A build check enforces it.

```tsx title="index.tsx"
// index.tsx - server
import { useId } from 'react'   // allowed
import { use } from 'react'     // allowed

// anything else fails check-boundaries:
// useState, useEffect, useRef, useMemo, useCallback
```

## How a split component works

The server half renders the markup and resolves anything needing the server, such as icon names. The client half adds the one behaviour.

```tsx title="tag/index.tsx"
// tag/index.tsx - server
export function Tag({ onRemove, children, ...rest }: TagProps) {
  if (onRemove) {
    return <Removable onRemove={onRemove} {...rest}>{children}</Removable> // the x is a client part
  }
  return <span {...rest}>{children}</span> // still server
}
```

## How sizes are checked

Every client component has a size budget: 6 KB gzipped for a simple control, 14 KB for an overlay. `pnpm size --check` fails the build when one is crossed; React and Base UI are left out, because a page loads them once.

<Callout tone="info">The chips print the number `pnpm size` measured, so a chip cannot drift from the build.</Callout>

## What it costs you

Server-first comes with constraints. These are the ones you will notice.

<Cards columns={3}>
  <Card title="No onClick on a server component">A Button rendered on the server submits a form or follows a link. If it must run code in the browser, it lives in a client file.</Card>
  <Card title="A command palette needs a client file">`getKey`, `getLabel` and `onSelect` are functions, so Command must be configured in a file marked `'use client'`. Select and Combobox take plain data and render from a server file.</Card>
  <Card title="Some controls wait for hydration">Checkbox, Switch and Select submit their default value until JavaScript loads. Input and Textarea need no JavaScript at all.</Card>
</Cards>
