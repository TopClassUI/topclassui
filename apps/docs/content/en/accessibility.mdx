## Contrast

Contrast is measured from the real token values in every mode, as part of the build. Anything within 0.15 of a threshold counts as failing.

| What | Minimum |
|---|---|
| Body and muted text | 4.5:1 |
| A tone text on its own soft tint | 4.5:1 |
| A control boundary, on every surface it can sit on | 3:1 |
| The focus ring | 3:1 |
| Icons that carry meaning | 3:1 |

## Target size

Every interactive element is at least 24 by 24 CSS pixels, and grows to 44 on touch and other coarse pointers.

```tsx check title="save-button.tsx"
import { TOUCH_TARGET } from 'topclassui/classes'

export function SaveButton() {
  return <button type="button" className={TOUCH_TARGET}>Save</button>
}
```

The shared class every control carries, and your own controls can carry it too. Its value: <code>{TOUCH_TARGET}</code>

## Every drag has a keyboard path

[WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html). A Slider takes arrow keys. A Drawer and a Toast always render a close button.

## Focus is always visible

One focus ring on every control: a CSS outline with an offset, so the gap shows the real background on any surface. `--tc-ring` reaches 3:1 on every surface.

```tsx check title="home-link.tsx"
import { FOCUS_RING } from 'topclassui/classes'

export function HomeLink() {
  return <a href="/en" className={FOCUS_RING}>Home</a>
}
```

Its value: <code>{FOCUS_RING}</code>

## Labels are enforced by the types

An Input outside a Field needs an `id`, an `aria-label` or an `aria-labelledby`, and TypeScript rejects one without.

<WrongRight>

```tsx
<Input placeholder="Email" />
// Type error: id, aria-label or aria-labelledby is required
```

```tsx check
import { Field } from 'topclassui/field'
import { Input } from 'topclassui/input'

export function Email() {
  return (
    <Field name="email" label="Email">
      {(control) => <Input {...control} type="email" />}
    </Field>
  )
}
```

</WrongRight>

## Automatic and manual

| Check | How | When |
|---|---|---|
| Contrast | `check-contrast.ts` | Every `pnpm check` |
| ARIA and roles | [axe-core](https://github.com/dequelabs/axe-core) in every demo | Every `pnpm check` |
| Target size | A browser test measures every focusable element | Every `pnpm check` |
| Keyboard behaviour | A test per interactive component, following the [ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) | Every `pnpm check` |
| Screen reader | NVDA and VoiceOver, by hand | Before each release |
| Forced colors | Windows high contrast, by hand | Before each release |

## Known gaps

Contrast is measured on every build. Axe, target size, the focus ring and long text inside its control are checked in a real browser on every demo, in 3 modes and 2 directions, and the interactive components have keyboard tests. Screen readers (NVDA, VoiceOver) and forced colors are checked by hand, and that has not been done yet.

<Callout tone="warning">Forced-colors mode is a manual check. A layout that relies on background fills disappears there, so every component is drawn with borders.</Callout>
