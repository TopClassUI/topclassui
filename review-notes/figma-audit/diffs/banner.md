# banner: Figma frame vs live build

Verdict: **major**. Blockers 0, major 2, minor 4.

| Area | Figma frame | Built | Fix | Severity |
|---|---|---|---|---|
| Action slot (stage sample) | "Read more" is a bold 14px text link in the tone's own text colour (81,162,255): no border, no box, no radius, centred on the message block, 16px before the x | A 32px-tall outlined Button (1px grey 161,161,161 border, ~8px radius, ~20px side padding, 125px wide) sits in the action slot; the bar's height is set by that button | Make the demos and the docs default pass a link-styled action (Button variant="link" size="sm" tone={tone}, or an anchor with font-semibold) instead of variant="outline"; basic.tsx, states.tsx and playground.tsx all use the outline button | major |
| Vertical padding / bar height | ~8px top and bottom: the two-line 14/20 sample is 57px tall (fill y 214-270), text cap top 14px below the fill edge | py-3 = 12px each side: a one-line banner is 44px tall (y 32-75 in the states capture), 56px with the button; a two-line one would be ~64px vs 57 | variants.ts: py-3 -> py-2 on the root | major |
| Message type weight | Message text is regular (400) at 14px; only the action link is bold | Root carries font-medium, so the message reads semibold while the action is the same weight as the message | Drop font-medium from the root in variants.ts and give the action/link font-semibold | minor |
| Per-tone icons (states strip) | primary draws no leading icon, info draws a circle-i, warning draws a warning triangle | states.tsx passes the same circle-i `info` glyph to all six tones, so Warning shows a circle-i and Primary shows an icon the frame lacks | states.tsx: pass the tone's glyph (warning triangle for warning, none for primary) or map a default icon per tone in index.tsx | minor |
| Info tone text colour | info chip text and icon both sample ~2,169,229 (#02A9E5) on the 15,31,43 info tint | Info text 7,188,255 (#07BCFF) and icon 2,175,237 on the same 15,31,43 tint: lighter and bluer | Compare --tc-info-on-soft (dark) with the Figma info/on-soft variable; primary (81,162,255) and warning (255,185,0) match exactly, only info drifts | minor |
| Dismiss x inset | x glyph (10x9px, 64,129,206) ends 20px from the banner's end edge, on the padding line | x glyph (~10x10px, 3,162,220) ends ~27px from the end edge because the ICON_BUTTON box sits inside px-5 | Pull the x button back by its own inner padding (-me-1 or -me-2 in DISMISS) so the glyph sits on the 20px line | minor |

Notes: Sample content differs and is not counted: the frame's stage is tone primary, "Version 0.2 is out, with a Drawer and full RTL support.", a "Read more" link and an x, with no leading icon; the live basic demo is tone info, "Version 2 is out, with faster builds and a new theme editor.", a bell icon and a "Read the changelog" button, not dismissible. Matches: fill colours for primary (16,30,59) and warning (37,27,16) and their text (81,162,255 / 255,185,0), 20px horizontal padding, 14px/20px text, square corners (radius 0), no border, no shadow, x glyph size and the action-then-x order. The stage draws the sample 460px wide centred in the docs stage while the build is full width; that is docs-card sizing, not counted. The Try-it panel lists variant (soft), placement (top) and sticky, which the build has no props for (no solid variant, no bottom placement, no sticky); the states strip does not draw them so they are not rows. The frame's "dismissed" state is a "hidden" placeholder meaning nothing renders; the build returns null once dismissed, so it is implemented but not capturable. The With-action button's grey border under tone="info" is Button's concern, not Banner's.
