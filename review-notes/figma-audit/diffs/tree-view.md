# tree-view: Figma frame vs live build

Verdict: **major**. Blockers 0, major 4, minor 5.

| Area | Figma frame | Built | Fix | Severity |
|---|---|---|---|---|
| geometry / row height | Stage rows sit on a 31px pitch; the selected tint is 30px tall (y 228-257), so the tree reads as a compact list | 40px pitch (--tc-row-height = 2.5rem); the selected tint is 40px tall (y 121-161), about 30% taller per row | Give the tree a 2rem row (its own knob or size-driven) instead of the 40px control height, and set TREE_VIEW_ROW_ESTIMATE to the same number | major |
| geometry / box height and padding | Even ~10px padding above the first and below the last row (5 rows in a 170px box) | max-h = --tc-list-rows x --tc-row-height (7 x 40 = 280px) ignores the 8px p-2, so at 7 rows the last row is cut by 8px and sits flush on the bottom edge (basic capture: box 32-312, package.json row 281-321) | Add the block padding to the cap, e.g. max-h-[calc(var(--tc-list-rows)*var(--tc-row-height)+2*--spacing(2))], or move the padding into the --tc-list-pad-start/--tc-list-pad-end spacers | major |
| states / loading | Two rounded muted skeleton bars (~100px and ~80px wide, ~8px tall, 12px apart), no text | Muted 14px text 'Loading' and 'Loading more' from TREE_VIEW_NOTE, no bars, no raised box | Render a TreeViewSkeleton of two or three row-shaped bars inside the raised box for status=loading, append skeleton rows under the list for loading-more, and keep the live-region text sr-only | major |
| states / empty | A centred muted inbox/tray icon (~24px), no text | Left-aligned muted text 'Nothing here yet', no icon, no box | empty-state.tsx: the inbox icon centred inside the raised box with labels.state.empty as a muted caption under it | major |

| icons / colour | Chevron and folder/file icons share the body colour with the label | TREE_VIEW_CARET and TREE_VIEW_ICON are text-muted (grey) on every unselected row | Use text-body on the caret and icon wrappers, keeping primary-on-soft on a selected row | minor |
