# file-upload: Figma frame vs live build

Verdict: **major**. Blockers 0, major 3, minor 5.

| Area | Figma frame | Built | Fix | Severity |
|---|---|---|---|---|
| Zone prompt layout | One centred line 'Drag files here or browse', ~15px medium in the body colour; 'browse' is inline, same colour, no underline | Two stacked lines: 'Drop files here' (text-sm font-medium) then 'Browse' on its own line in primary with an underline (FILE_UPLOAD_PROMPT is flex-col gap-0.5, FILE_UPLOAD_BROWSE adds text-primary-on-soft underline) | Make FILE_UPLOAD_PROMPT a wrapping row (flex flex-wrap justify-center gap-x-1) so the browse word follows the drop text on one line; drop the underline and primary tint (or keep primary only if a DECISIONS entry requires a distinguishable control) | major |
| File row: upload progress | Stage sample and the 'uploading' state draw a 4px rounded primary progress bar on a muted track under the file name (~200px wide, ~65% filled) inside a ~46px row with a solid 1px line | No progress exists: a row is file icon + name + size text + X (FILE_UPLOAD_ROW in classes.ts, client.tsx 74-92); nothing models an upload in progress (not captured live: the basic demo has no file) | Needs a decision (R-8.5-2 says components never fetch): either accept per-file status/progress as data (e.g. a `files` metadata prop or row render callback) and draw a 4px bar (bg-primary-solid on bg-line, rounded-full) under the name, or remove 'uploading' from the frame; record it in docs/DECISIONS.md | major |
| File row: done state | 'done' draws a success check-circle icon in front of muted 'done' text | No done state; a kept row keeps the muted file icon and the size text | Same decision as the progress row: once a per-file status is 'done', swap the row icon for check-circle in text-success-on-soft and the note for the done label | major |
| File row: error state | Danger alert-circle icon followed by the reason ('too big') in the light muted text colour; the zone itself does not change | warning-circle in text-danger-on-soft + reason in text-xs text-danger-on-soft (FILE_UPLOAD_REJECTED_ICON / FILE_UPLOAD_REASON); same structure, reason text is danger-toned (not captured live) | Set FILE_UPLOAD_REASON to text-xs text-muted so only the icon carries the danger hue; add a rejected row to dummy/states.tsx so it is captured | minor |
| Drag-over line | Line stays dashed and turns primary; primary tint fill; icon and text primary | FILE_UPLOAD_ZONE sets data-dragging:border-solid in addition to border-primary-solid, bg-primary-soft and text-primary-on-soft (not captured live) | Remove data-dragging:border-solid so the dashed primary line matches the frame, or record the solid line in docs/DECISIONS.md | minor |
| Upload icon size | Upload glyph ~20px | <Svg icon={uploadSimple} size="1.75rem" /> = 28px | size="sm" (20px) on the zone icon in client.tsx line 47 | minor |
| Zone rhythm and type | Padding ~26px; icon→prompt ~12px, prompt→hint ~8px; prompt ~15px, hint ~13px | p-6 (24px), gap-2 (8px) between icon, prompt and hint; prompt text-sm (14px), hint text-xs (12px) | Add mb-1 to FILE_UPLOAD_ICON (icon→prompt 12px) and keep gap-2 below the prompt; the 1px type differences are within tolerance | minor |
| File row surface | Row sits on the raised surface (same as the zone) with a solid 1px line and ~8px radius | FILE_UPLOAD_ROW has BORDER and rounded-control but no background, so it reads as the page surface (not captured live) | Add bg-surface to FILE_UPLOAD_ROW | minor |

Missing states: drag over, uploading (file row with progress bar), done, error (rejected file row)

Notes: Sample content differs and is not counted: the frame says 'Drag files here or browse' while the build says 'Drop files here' / 'Browse'; the frame's stage sample has a picked file 'brief.pdf' while the basic demo has no file; the 'Attachment', 'Invalid' and 'Disabled' labels are demo wrappers (a plain <label>), not the component. The frame's sample is 320px centred and the build fills 880px: a container choice, not counted. The build's zone-level invalid state (danger dashed line, muted hint) is not drawn in the frame, so it is not counted either. Idle and disabled match in role colours, dashed 1px line, radius (~10px) and 50% dimming; the invalid zone line is danger as the demo comment says. Rows 2-5 and 8 are read from classes.ts and client.tsx because no live capture shows a file row or a drag; dummy/states.tsx should render a kept row and a rejected row so the next audit can measure them. The lifecycle gap (uploading/done) follows from R-8.5-2 (the component never uploads), so it is one decision: per-file status as data, or a frame change. Font family ignored as instructed.
