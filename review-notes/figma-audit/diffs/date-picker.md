# date-picker: Figma frame vs live build

Verdict: **major**. Blockers 0, major 4, minor 6.

| Area | Figma frame | Built | Fix | Severity |
|---|---|---|---|---|
| Calendar popover: height and row pitch | Compact popover ~269x158 px; day rows ~19-24 px apart, weekday row to first week ~24 px, numbers ~12 px; whole month fits in ~160 px | Popover 280x274 px; day rows 36 px apart (cells ~35x36), ~16 px inner padding vs ~12 px in the frame; the calendar is ~73% taller | Reduce the day-cell height and row gap toward the frame's compact grid, but keep the 24 px minimum target (44 px under pointer-coarse, R-5.6-2); the frame's 19 px rows are under the floor, so settle the cell height in DECISIONS.md rather than copying it | major |
| Selected day shape | Blue primary pill, fully rounded (rounded-full), ~33x16 px around '22', white text | Blue rounded square ~33x29 px with ~6 px radius around '22' | Use the full-radius pill for the selected day (or the --tc-radius knob at its full value) instead of the control radius | major |
| States strip coverage | Six states drawn: idle, open, selected, today, disabled, invalid, each as a closed trigger with its name | The states capture renders one instance only: an empty 'Pick a date' trigger with the October calendar open; no idle, selected, today, disabled or invalid trigger is drawn | Make the states demo render six closed triggers (idle, open with ring, selected value, today, disabled, invalid) side by side instead of a single opened picker | major |
| Open state: focus ring on trigger | Open trigger carries a 2 px blue (primary) ring with ~2 px offset around the control | Trigger shows no ring while the popover is open; no focus ring is visible anywhere in the capture | Mark the trigger with data-open and draw the RING classes from shared/classes.ts on it while open (or keep focus-visible on the trigger when the popover opens); if focus moves into the grid, the grid day should show the ring | major |
| Popover header: close button | Header is prev chevron, centred 'September 2026', next chevron; no close control | Header adds an 'X' close button at the far end after the next chevron | Remove the close button from the calendar header (Escape and outside click close the popover) or hide it unless a prop asks for it | minor |
| Popover border and radius | Popover has a visible 1 px lighter line border on the raised surface, radius ~10 px | No visible border; radius ~12 px | Add border-line to the popover panel and use the panel radius knob value the frame uses (~10 px) | minor |
| Trigger border and height | Trigger ~128x40 px, raised surface with no distinct border line, radius ~6 px | Trigger ~192x38 px with a clearly visible 1 px grey line border, radius ~6 px | Match the frame's borderless raised surface (or a border at --tc-line, not line-strong) and check the md control height resolves to 40 px, not 38 | minor |
| Day number and weekday type | Day numbers ~12 px regular weight body colour; weekday letters ~10 px muted; month title ~15 px semibold | Day numbers ~13 px semibold; weekday letters ~11 px bold muted; month title ~14 px bold | Drop the day numbers and weekday labels to the frame's regular/medium weight and one step smaller; title to semibold | minor |
| Week start | Weekday row starts Monday: M T W T F S S (Try it shows firstDayOfWeek 1), September 1 sits under T with one empty cell | Weekday row starts Sunday: S M T W T F S, September 1 under T with two empty cells | Set the preview demo's firstDayOfWeek to 1 to match the frame, or make 1 the schema default if that is what the Try it panel implies | minor |
| Trigger text size | Trigger label ~13 px, calendar icon ~16 px muted at the start | Trigger label ~14 px, same icon placement | Use the sm text step for the md trigger label if the frame's 13 px is intended; otherwise leave | minor |

Missing states: idle (closed trigger), selected (closed trigger with value), today (closed trigger), disabled, invalid

Notes: Sample content differs and is not counted: the frame's stage shows the calendar popover alone, while the live basic capture wraps the picker in a Field with a 'Check-in' label and a trigger above the popover; the date format is '22 Sep 2026' in the frame vs 'Sep 22, 2026' in the build (locale formatting); the states capture shows October 2026 with 19 underlined as today, whereas the frame's calendar is September 2026 with 22 selected and no separate today marker, so the today-in-grid styling (bold + underline) cannot be compared. The frame's grid stops at 27 and omits the 28-30 row, which looks like a frame truncation rather than a design intent; the build draws it. The frame's ~19 px day rows are below the 24 px target floor of R-5.6-2, so the row-pitch finding should be reconciled with the rule (and the 44 px pointer-coarse floor) in DECISIONS.md rather than copied literally. Font-family differences were ignored as instructed.
